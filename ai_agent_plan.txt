دليل بناء ودمج الذكاء الاصطناعي (AI Agent) في مشاريع Laravel
(توضيح المسار الفعلي والروابط المستخدمة حالياً في مشروع Sketo)

هذا الدليل يوضح لك الخطوات التفصيلية لنقل فكرة الـ "AI Agent" الذي تم بناؤه في مشروع Sketo وتطبيقها في أي مشروع Laravel آخر.
فكرة الـ Agent هنا تعتمد على برمجة مخصصة (Custom Integration) داخل Laravel، وليست حزمة (Package) من GitHub.

--------------------------------------------------
أولاً: ما هو الـ API المستخدم حالياً؟ (الروابط)
--------------------------------------------------
حالياً، المشروع لا يستخدم إضافة (Repo) من GitHub لتشغيل الـ AI، بل يتصل مباشرة بـ API خارجي يسمى (Groq) الذي يقدم واجهة متوافقة مع OpenAI لتشغيل نماذج مفتوحة المصدر بسرعة فائقة.

الإعدادات الحالية في ملف `.env` هي:
AI_API_URL="https://api.groq.com/openai/v1/chat/completions"
AI_API_KEY="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"
AI_MODEL="qwen/qwen3-32b"  (أو أي موديل مدعوم من Groq)

--------------------------------------------------
ثانياً: مسار الـ AI Agent (كيف تذهب البيانات وتعود؟)
--------------------------------------------------
عندما يكتب المستخدم رسالة، تسير البيانات في هذا المسار الدقيق (Trace Path):

1. الواجهة (Frontend): المستخدم يكتب رسالة ويتم إرسالها عبر AJAX (JavaScript) إلى مسار (Route) في Laravel.
   الرابط الداخلي: POST /ai/chat

2. الـ Router (routes/web.php): يستقبل الطلب ويوجهه إلى الكنترولر `AiChatController` وتحديداً دالة `handleChat`.

3. الكنترولر (AiChatController.php): 
   - يقوم بحفظ رسالة المستخدم في قاعدة البيانات (جدول ai_messages).
   - يقوم ببناء "رسالة النظام الافتراضية" (System Prompt) التي توجه الذكاء الاصطناعي (مثل: أنت مستشار أعمال، استخدم الجنيه المصري، الخ).
   - يقوم بتجميع تاريخ المحادثة بالكامل.
   - يرسل كل هذه البيانات إلى خدمة الـ AI: `$aiAgent->ask($messages)`

4. خدمة الـ AI (AiAgentService.php): هذا هو "العقل المدبر".
   - دالة `getTools()`: تقوم بتعريف جميع الدوال المتاحة للذكاء الاصطناعي كأدوات (Function Calling) مثل جلب المبيعات (get_sales_overview).
   - دالة `askOpenAI()`: تقوم بتجهيز الطلب النهائي (الرسائل + الأدوات) وترسله باستخدام `Http::post` إلى رابط Groq API المذكور في `.env`.

5. واجهة برمجة تطبيقات Groq (الـ API الخارجي):
   - يقرأ الـ API الرسالة، وإذا وجد أن المستخدم يسأل عن المبيعات، يرد على الـ Service ويقول: "من فضلك قم بتشغيل أداة get_sales_overview".
   
6. خدمة الـ AI (مرة أخرى):
   - دالة `executeTool()`: تلتقط هذا الطلب، وتتصل بقاعدة بيانات Laravel (مثلاً جدول المبيعات Sales أو المنتجات Product)، وتستخرج البيانات الحقيقية وتصيغها كـ JSON.
   - يتم إرسال هذا الـ JSON مرة أخرى إلى Groq API.
   
7. الـ API يعيد الرد النهائي:
   - يقرأ Groq الـ JSON ويبني إجابة نصية بشرية (مثال: "مبيعاتك اليوم هي 5000 جنيه مصري"). ويرسلها للـ Service.

8. العودة للمستخدم:
   - الكنترولر يستلم الإجابة النصية، يحفظها في قاعدة البيانات (دور المساعد assistant)، ثم يرسلها عبر JSON للـ Frontend.
   - الواجهة (JavaScript) تعرض الرسالة للمستخدم.

--------------------------------------------------
كيف تنفذ هذا في مشروع جديد؟ (الخطوات)
--------------------------------------------------
الخطوة 1: انسخ إعدادات Groq API وضعها في ملف `.env` في المشروع الجديد.

الخطوة 2: أنشئ Service جديد: `app/Services/AiAgentService.php` وضع فيه دالتي `getTools` لتعريف قواعد بياناتك، و `askOpenAI` للاتصال برابط Groq.

الخطوة 3: أنشئ Controller جديد: `app/Http/Controllers/AiChatController.php` لبناء הSystem Prompt وحفظ الرسائل في الـ DB وإرسالها للـ Service.

الخطوة 4: أنشئ جداول قواعد البيانات (Migrations) للمحادثات (AiChat و AiMessage) إذا أردت حفظ سجل الشات.

الخطوة 5: أضف الـ Routes (مثل `Route::post('/ai/chat', ...)`) وابنِ واجهة الـ JavaScript المطلوبة في ملفات الـ Blade.

* ملاحظة: يمكنك تغيير Groq واستخدام OpenAI الرسمي أو أي بروكسي محلي عن طريق تغيير المتغيرات في `.env` فقط، دون الحاجة لتغيير هيكلة الكود.
